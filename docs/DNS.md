# DNS for trusted mail, step by step

This is the walkthrough for a domain served by the bundled Stalwart. Tern
shows the same records with live checks under **Settings → Mail server**,
and `./bin/tern dns-check` prints them from the terminal. The records use
`example.com` for the mail domain and `mx1.example.com` for the mail host;
yours are filled in for you in the app.

## Where records go

- **Registrar or DNS host** (Cloudflare, Porkbun, Namecheap, deSEC, Route 53):
  everything below except reverse DNS. Open the zone for `example.com` and
  add records with the exact name, type and value shown. If the panel adds
  the domain for you, enter only the left part (`mx1`, `_dmarc`, `default._bimi`).
  For the domain itself use `@`.
- **Hosting provider** (Hetzner, OVH, RackNerd, …): only the reverse DNS
  (PTR) record, set on the server's IP in the provider's panel.

Set short TTLs (300 seconds) while setting up. Changes usually show up
within minutes; some resolvers cache for an hour. If Cloudflare proxies your
records, turn the orange cloud **off** for every mail-related name: mail
does not go through their proxy.

## 1. Required: the mail server's address

| Type | Name | Value |
|---|---|---|
| A | `mx1.example.com` | the server's IPv4 |
| PTR (reverse DNS) | the server's IPv4 | `mx1.example.com` |

Forward and reverse must match exactly. Gmail rejects mail from servers where
they do not. Check with:

```bash
dig +short mx1.example.com
dig +short -x 203.0.113.10
```

## 2. Required: receiving and authentication

| Type | Name | Value | Purpose |
|---|---|---|---|
| MX | `example.com` | `10 mx1.example.com` | where mail for the domain is delivered |
| TXT | `example.com` | `v=spf1 mx -all` | only the MX host may send for the domain |
| TXT | `mx1.example.com` | `v=spf1 a -all` | SPF for the host's own bounces |
| TXT | `v1-ed25519-….` `_domainkey.example.com` | `v=DKIM1; k=ed25519; …` | DKIM key 1, signs every message |
| TXT | `v1-rsa-….` `_domainkey.example.com` | `v=DKIM1; k=rsa; …` | DKIM key 2, for receivers without Ed25519 |
| TXT | `_dmarc.example.com` | `v=DMARC1; p=reject; rua=mailto:postmaster@example.com` | reject spoofed mail, get reports |

The DKIM values are long; copy them from the app, they are generated by the
server and rotate on a schedule (old keys stay valid for a week). Long TXT
values are split into quoted chunks in some panels; paste the whole thing
and the panel splits it for you.

Only one SPF record may exist on a name. If a website form or another
provider already added one, merge them into a single record.

DMARC at `p=reject` is the goal and what the server generates. If you are
nervous, start at `p=quarantine` for a week and read the reports, then move
to reject. BIMI requires quarantine or reject.

## 3. Recommended: encryption in transit

| Type | Name | Value |
|---|---|---|
| CNAME | `mta-sts.example.com` | `mx1.example.com` |
| TXT | `_mta-sts.example.com` | `v=STSv1; id=…` |
| TXT | `_smtp._tls.example.com` | `v=TLSRPTv1; rua=mailto:postmaster@example.com` |

MTA-STS tells other servers to deliver to you only over verified TLS. The
policy file is served by the mail server through Caddy at
`https://mta-sts.example.com/.well-known/mta-sts.txt`; the CNAME makes that
name resolve here and Caddy fetches a certificate for it on first use. Keep
the mode on **testing** until the DNS checks pass, then switch to
**enforce** in Settings → Mail server. TLS-RPT sends you a daily report if
anyone failed to connect securely.

## 4. Brand logo (BIMI)

BIMI shows your logo beside your messages in mail clients that support it.
Three things are needed:

1. **DMARC** at `p=quarantine` or `p=reject` with `pct=100` (the default).
2. **The logo** as an SVG in the "Tiny Portable/Secure" profile: square,
   no scripts, no external references, under 32 KB. Upload your own SVG in
   Settings → Mail server → Brand logo, or let Tern generate a default
   avatar from initials and a colour. Tern hosts it at
   `https://<your web host>/bimi/example.com.svg`.
3. **The record**:

| Type | Name | Value |
|---|---|---|
| TXT | `default._bimi.example.com` | `v=BIMI1; l=https://outreach.example.com/bimi/example.com.svg; a=;` |

Yahoo, Fastmail, La Poste and others display the logo from this alone.
Gmail and Apple Mail also require a Verified Mark Certificate (VMC) or
Common Mark Certificate (CMC) from DigiCert or Entrust, which is a paid
certificate tied to a registered trademark (VMC) or a logo in use for a
year (CMC). If you buy one, upload the `.pem` to a public URL and add it as
`a=https://…/vmc.pem` in the record. Without it the logo still appears in
the clients that do not require one, and inside Tern for every message from
your domain.

## 5. Mail apps configure themselves

The remaining CNAME, SRV and `_ua-auto-config` records let Thunderbird,
Apple Mail, Outlook and phones set up an account from just the address and
password. Optional, but they remove a support question.

## 6. Check everything

- Settings → Mail server → **Check DNS**: every record shows found, missing
  or differs, with what the resolver returned.
- `./bin/tern dns-check --port25` does the same from the terminal and also
  tests whether the hosting provider allows outbound port 25.
- Send a message to a Gmail address and open "Show original": SPF, DKIM and
  DMARC should all say PASS.
- Send to a mail-tester.com address for a score out of ten.

## 7. Before you send in volume

- Warm the mailbox up: 20 to 30 messages a day for two weeks, then raise
  the daily cap in the account's sending policy.
- Watch the DMARC and TLS reports arriving at `postmaster@example.com`.
- Keep the unsubscribe footer on for sequences and the suppression list
  respected; a spam complaint rate above 0.3% at Gmail undoes everything
  above.
